# Practical-02 – File Copy and System Call Tracing

## Objective

To develop a C program using the system calls `open()`, `read()`, `write()`, and `close()` to copy the contents of one file to another.

To understand the transition between user space and kernel space during system call execution.

To use the `strace` utility to trace and analyze the system calls generated by `cat sample.txt`.

## 1. File Copy Program

### Source Code

```c
#include <stdio.h>
#include <fcntl.h>
#include <unistd.h>

int main()
{
    int source, destination;
    char buffer[1024];
    ssize_t bytesRead;

    source = open("sample.txt", O_RDONLY);

    if (source < 0)
    {
        printf("Error opening source file\n");
        return 1;
    }

    destination = open("copied.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);

    if (destination < 0)
    {
        printf("Error opening destination file\n");
        close(source);
        return 1;
    }

    while ((bytesRead = read(source, buffer, sizeof(buffer))) > 0)
    {
        write(destination, buffer, bytesRead);
    }

    close(source);
    close(destination);

    printf("File copied successfully\n");

    return 0;
}
```

## 4. User Space and Kernel Space Transition

The C program runs in user space. When it needs to perform file operations, it requests services from the Linux kernel through system calls.

The basic transition is:

```text
User Space
    |
    | System Call
    v
Kernel Space
    |
    | File operation
    v
Kernel Space
    |
    | Return result
    v
User Space
```

### System calls used

* `open()` – requests the kernel to open a file and returns a file descriptor.
* `read()` – requests the kernel to read data from the source file into the user-space buffer.
* `write()` – requests the kernel to write data from the buffer to the destination file.
* `close()` – requests the kernel to close the file descriptor.

Thus, whenever the program calls these functions, control temporarily moves from user space to kernel space. After the requested operation is completed, control returns to the user-space program.

## 5. System Call Tracing Using strace

The command used was:

```bash
strace cat sample.txt
```

The trace produced many system calls because `cat` first loads libraries and performs initialization before accessing the requested file.

The important system calls related to `sample.txt` were:

```text
statx(AT_FDCWD, "sample.txt", ...) = 0
openat(AT_FDCWD, "sample.txt", O_RDONLY|O_CLOEXEC) = 3
fstat(3, ...) = 0
fstat(1, ...) = 0
splice(3, NULL, 1, NULL, 1048576, 0) = -1 EINVAL
pipe([4, 5]) = 0
splice(3, NULL, 5, NULL, 1048576, 0) = 47
splice(4, NULL, 1, NULL, 47, 0) = 47
splice(3, NULL, 5, NULL, 1048576, 0) = 0
close(5) = 0
close(4) = 0
close(3) = 0
exit_group(0) = ?
```

## 6. Analysis of Important System Calls

| System Call    | Purpose                                                   |
| -------------- | --------------------------------------------------------- |
| `execve()`     | Starts the `cat` program.                                 |
| `statx()`      | Obtains information about `sample.txt`.                   |
| `openat()`     | Opens `sample.txt` for reading.                           |
| `fstat()`      | Obtains information about the opened file and output.     |
| `splice()`     | Transfers file data efficiently between file descriptors. |
| `pipe()`       | Creates a pipe used during the data transfer.             |
| `close()`      | Closes the file descriptors after use.                    |
| `exit_group()` | Terminates the `cat` process.                             |

The trace shows that `sample.txt` was opened successfully with file descriptor `3`.

The first `splice()` attempt returned `EINVAL`, indicating an invalid argument for that operation. `cat` then created a pipe and successfully used `splice()` to transfer the 47 bytes of the file to standard output.

The successful transfer can be seen from:

```text
splice(3, NULL, 5, NULL, 1048576, 0) = 47
splice(4, NULL, 1, NULL, 47, 0) = 47
```

The value `47` corresponds to the 47-byte size of `sample.txt`.

## 7. Conclusion

The C program successfully copied `sample.txt` to `copied.txt` using `open()`, `read()`, `write()`, and `close()` system calls.

The `diff` command confirmed that the source and destination files were identical.

The `strace` analysis showed how the `cat` command interacts with the Linux kernel through system calls. Important kernel services involved file access, file information retrieval, data transfer, pipe creation, descriptor management, and process termination.
